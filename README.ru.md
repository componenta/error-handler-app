# Componenta Error Handler App

Интеграция обработки ошибок для Componenta-приложения. Пакет регистрирует рендереры с учетом режима отладки и слушатели файлового/HTML-логирования, которые используют базовые сервисы `componenta/error-handler`.

Базовые контракты, контексты, обработчики, рендереры, промежуточные обработчики и генераторы HTTP-ответов находятся в `componenta/error-handler`. Этот пакет подключает их к приложению через `Componenta\Error\App\ConfigProvider`.

## Установка

```bash
composer require componenta/error-handler-app
```

Пакет публикует `Componenta\Error\App\ConfigProvider` через метаданные Composer.

## Поведение отладки

`APP_DEBUG=true` управляет тем, увидит ли пользователь подробную HTTP-ошибку. Когда отладка отключена, рендерер приложения использует безопасный шаблон `templates/error/500.phtml` через `Componenta\Error\Renderer\SafeRenderer`.

`EnvDebugResolver` использует снимок окружения собранного Config. При начальной загрузке проверяются локальное окружение процесса, затем `$_ENV`, затем файлы `.env` и `.env.local` через парсер Config. Более поздние присваивания имеют приоритет. Явное отключение, некорректная или недоступная конфигурация не включают отладку.

Значения `1`, `true`, `yes` и `on` включают отладку. Отсутствующий `APP_DEBUG` и любые другие значения отключают отладку.

## Логирование

`Componenta\Error\App\Listener\FileLogListener` пишет структурированные записи JSON Lines. `Componenta\Error\App\Listener\HtmlLogListener` пишет HTML-снимки для просмотра в браузере. Пути разрешаются через `componenta/path-resolver`.

`FileLogListener` регистрируется для HTTP и CLI ошибок. `HtmlLogListener` регистрируется только для HTTP ошибок и пишет снимки только при включенном `APP_DEBUG`.

### Необязательное журналирование через PSR-3

Приложение регистрирует фабрику слушателя ядра `Componenta\Error\Listener\Psr3ErrorListener`, но не добавляет его в список слушателей по умолчанию. Для подключения зарегистрируйте реальный сервис `Psr\Log\LoggerInterface` и добавьте слушатель в карту регистрации ошибок:

```php
use Componenta\Error\App\ConfigKey;
use Componenta\Error\Listener\Psr3ErrorListener;

return [
    ConfigKey::ERROR_LISTENERS => [
        Throwable::class => [Psr3ErrorListener::class],
    ],
];
```

Config 4 дополняет списки слушателей. Чтобы заменить все стандартные регистрации журналированием через PSR-3, используйте `ConfigKey::ERROR_LISTENERS => \Componenta\Config\ConfigOverride::replace([Throwable::class => [Psr3ErrorListener::class]])`. Отсутствующий или некорректно типизированный логгер приводит к ошибке явной настройки слушателя, а не к скрытой потере ошибок. Стандартная фабрика не передаёт исходный объект исключения; для доверенного диагностического хранилища переопределите сервис слушателя с помощью `new Psr3ErrorListener($logger, includeException: true)`.

## Регистрируемые сервисы

`Componenta\Error\App\ConfigProvider` настраивает:

| Ключ или сервис | Значение |
|---|---|
| `ConfigKey::ERROR_LISTENERS` | `FileLogListener`, `HtmlLogListener` |
| `ConfigKey::HTTP_RENDERER` | `PrettyPageRenderer(debug: true)` в режиме отладки, иначе `SafeRenderer` с `templates/error/500.phtml`. |
| `ConfigKey::CLI_RENDERER` | `PlainTextRenderer(debug: true)` в режиме отладки, иначе `SafeCliRenderer`. |
| `SafeRenderer::class` | Безопасный рендерер, привязанный к `templates/error/500.phtml`. |

Пакет предоставляет все ключи конфигурации Componenta, фабрики сервисов, псевдонимы, выбор рендереров, обнаружение слушателей и регистрацию политики. Базовые обработчики остаются в error-handler.

## Связанные пакеты

- [`componenta/error-handler`](../error-handler/README.ru.md) определяет базовые контракты и обработчики ошибок.
- [`componenta/http-emitter`](../http-emitter/README.ru.md) отправляет HTTP-ответы.
- [`componenta/skeleton`](../../componenta-skeleton/README.ru.md) показывает, как точки входа приложения логируют ошибки загрузки и рендерят безопасный шаблон 500 для HTTP-сценариев.

## Переход на версию 2 и безопасность эксплуатации

Требуются Config 4 и Error Handler 2. Зависимости от среды выполнения приложения и HTTP-эмиттера удалены. По умолчанию журналы сохраняются в `log/error-handler`. Записи содержат идентификатор ошибки; URI запросов и аргументы команд не записываются. На POSIX-системах каталог должен быть закрытым (0700), файлы создаются с правами 0600. HTML-снимки создаются без перезаписи, ограничены 2 МиБ на снимок и по умолчанию отключены при самостоятельном создании слушателя. Размещайте каталог вне публичной директории и настройте ротацию и срок хранения средствами окружения. Отладочный вывод может содержать конфиденциальные сообщения исключений и исходный код; включайте его только в доверенной среде.

Рендереры возвращают объект `RenderedError` из ядра (`content`, `contentType`, `Stringable`). HTML-снимки используют этот же контракт без отдельного метода HTTP-рендеринга.

Приложение регистрирует единый репортёр, не зависящий от транспорта. Файловый журнал обрабатывает HTTP- и CLI-события, а HTML-снимки — только HTTP при включённой отладке. Слушатели получают обязательный `ErrorOccurrence` через `$event->error`, HTTP-статус — из контекста.

## Регистрация и обнаружение слушателей

Для настройки регистрации используется Componenta\Error\App\ConfigKey:

```php
return [
    ConfigKey::ERROR_LISTENERS => [
        Throwable::class => [FileLogListener::class],
        RuntimeException::class => [
            ['listener' => MonitoringListener::class, 'priority' => 100],
        ],
    ],
    ConfigKey::ERROR_LISTENER_CLASSES => [CustomAttributedListener::class],
    ConfigKey::NON_REPORTABLE_ERRORS => [ExpectedException::class],
];
```

Приложение создаёт составной провайдер (сначала явные регистрации, затем регистрации по атрибутам). Обозначайте конкретные классы слушателей атрибутом #[\Componenta\Error\Event\Attribute\ListenTo(RuntimeException::class, priority: 10)] и обеспечьте их разрешение по имени класса через контейнер. Если приложение предоставляет Componenta\ClassFinder\ClassIteratorInterface, существующие результаты обнаружения используются один раз при создании провайдера; дополнительное сканирование файловой системы не запускается. Значение false для ConfigKey::DISCOVER_ERROR_LISTENERS отключает автоматическое обнаружение. Если итератор обнаруженных классов отсутствует, работает явно настроенный список кандидатов. Разрешите ErrorListenerProviderInterface при инициализации приложения, чтобы подготовить маршрутизацию до обработки ошибок. Провайдер ядра не зависит от ClassFinder или среды выполнения приложения. Выбор часов и создание события остаются ответственностью репортёра.

Каталог журналов и его родительские каталоги должны контролироваться окружением развёртывания. Конечный каталог не должен быть символической ссылкой, в том числе при завершающих разделителях или компонентах `.`; идентичность файла повторно проверяется после получения блокировки записи. Внешняя ротация должна быть согласована с приложением.

Регистрируется только `Componenta\Error\App\ConfigProvider`. Самостоятельное ядро больше не содержит провайдера конфигурации и ключей Componenta. Для настроек HTTP/CLI (`HTTP_FALLBACK_GENERATOR`, `HTTP_GENERATORS`, `CLI_FALLBACK_HANDLER`, `ERROR_LEVEL`, рендереров и регистрации ошибок) используйте `Componenta\Error\App\ConfigKey`. Строковые значения ключей сохранены.

`HtmlLogListener` принимает любую реализацию `ErrorRendererInterface`. Слушатель проверяет поддержку исходной ошибки и HTTP-контекста, передаёт их без изменений и требует результат `text/html` (параметры допустимы). Неподдерживаемые ошибки пропускаются; результат другого типа вызывает `UnexpectedValueException` до записи файла. Повторный рендеринг с подменой `Accept` отсутствует. Фабрика приложения по-прежнему передаёт `PrettyPageRenderer(debug: true)` для включённых диагностических снимков. Пользовательский рендерер должен формировать HTML для всех поддерживаемых им ошибок в этом слушателе.
